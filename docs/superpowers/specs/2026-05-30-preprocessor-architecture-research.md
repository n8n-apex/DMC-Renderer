# Pre-processor Architecture — Research & Decision (ADR)

**Date:** 2026-05-30
**Question:** The pre-processor's logic is correct and working (221 tests). Are we building it the way an expert team would build a robust, typed, external-call-heavy data pipeline — or have we vibe-coded the *infrastructure* around good logic? What patterns/libraries should we adopt to make it more robust and higher-quality **without changing behavior**?
**Method:** 5 parallel deep-research agents (opus), each grounded in the actual `research/preprocessor/` code with file:line citations + web-sourced best practice: (A) orchestration & stage contracts; (B) FastAPI async & job handling; (C) external-call resilience; (D) config/secrets/observability/error-handling/testing; (E) modularity & Stage-6 deprecation. Sources cited inline.

> **Framing (non-negotiable):** This is a **low-volume internal tool for one agency**, triggered by an Airtable checkbox. Every recommendation is right-sized and YAGNI — heavyweight orchestration (Prefect/Dagster/Temporal/Celery/Kafka/k8s) is rejected as overkill, the same judgment the renderer ADR made on InDesign Server. The **cardinal brand-agnostic rule** holds throughout: no client name or hex/font literal in logic.

---

## TL;DR recommendation

**The stack is right; the wiring around it is under-built.** Stay on Python / FastAPI / Pydantic v2 / httpx. The logic is sound and tested — the gaps are all in cross-cutting *infrastructure* (config, observability, resilience, contracts), exactly the things you add once a prototype becomes a system. Adopt the following, in tiers by value/risk. **Everything is output-preserving — the 221 tests stay green; we only ADD tests.**

1. **Tier 0 — cheap, near-zero-risk, do first (the "free" wins).**
   - **One typed `Settings` (pydantic-settings `BaseSettings`)** loaded once + injected via `Depends`, replacing 10 scattered `os.getenv` calls + inline model-slug literals; `.env` loads in-process (so tests/scripts get it too, not just `uvicorn --env-file`). Secrets as `SecretStr`.
   - **One pooled `httpx.AsyncClient`** created in a FastAPI `lifespan`, injected via `Depends`. The stage functions *already* accept `http_client=…` — this is wiring, not a rewrite. (Today every call site builds its own client = no connection reuse.)
   - **Structured logging + a correlation/job id**, and **kill the two silent `except: pass` blocks** (`main.py:132,139`). There is currently **zero logging in the entire codebase.**

2. **Tier 1 — high-value robustness (protects money + the downstream seam).**
   - **Unify all retries under one policy** (recommend **`stamina`**): exponential backoff **+ jitter**, honor **`Retry-After`** on 429/503, retry only transient classes, per-service timeouts. Replaces three inconsistent ad-hoc behaviors (linear `0.5*attempt`, none, tight webhook loop).
   - **fal idempotency** (don't pay twice): content-addressed cache keyed by `sha256(model+prompt+params)` (skip the POST if the PNG exists) **+** switch to the **fal queue `request_id`** so a download failure re-fetches the *result* instead of re-generating.
   - **Per-report image budget guard** (`MAX_GENERATIONS_PER_REPORT`) → degrade to stub + warning when exceeded; fail-safe against silent overspend.
   - **A golden-file + schema contract test on `resolved_package.json`** (the Layer-1↔Layer-2 seam — the single most important artifact) **+ promote the manifest to a Pydantic model** so the contract is explicit and versioned.

3. **Tier 2 — architecture cleanup (legibility + testability).**
   - **Extract the pipeline body out of the `/render` route** into `run_render_pipeline(...)`, add a **small hand-rolled `Stage` Protocol + runner** (~60–100 LOC, stdlib only — mirror the existing `stages/onboard/pipeline.py` with its `_mark` per-stage timing). **Reject** Hamilton/Prefect/Dagster.
   - **Tighten the stage seams to typed contracts** — kill the raw dicts at boundaries (`components`, hand-built `brand_axes`, mid-pipeline `.model_dump()` round-trips); collapse the duplicated `_unpack_page` normalizers.
   - **Bring `/render` onto `/onboard`'s 202 + background + webhook pattern** (keep cheap validation synchronous so "reject loud" stays immediate) — removes the multi-minute-request timeout class.
   - **Split `generate_assets.py` (822 lines, 4 responsibilities)** into a small `stages/assets/` package.

4. **Tier 3 — deprecation (delete the legacy liability).**
   - **Retire Stage 6 (`generate_components.py`, 1,580 lines).** The consumer trace proves it's **dead on the render side**: SVGs are generated, written, and indexed, but **no rendered page consumes them** (the renderer already builds every visual from `page["data"]`; the apex package has 1 SVG, and the pattern that owns that page ignores it). Removes ~1,980 lines of source+test and the entire stale-**Inter**-font-width liability. Sequenced safely (neutralize producer → observe stable → delete).

5. **Stay on `BackgroundTasks` for now; do NOT add Redis/arq/Celery yet.** Mitigate the one real risk (process restart loses an in-flight paid job) with the disk-fallback `/onboard` already has + idempotent webhook payloads keyed on `record_id`. Adopt **arq** (lightest asyncio-native upgrade) only if durable retries, a job-status endpoint, or concurrency later force it. **Circuit breakers: YAGNI** (one sequential run per checkbox — nothing to protect).

## Finding A — Orchestration & inter-stage contracts

**Current state.** The `/render` handler (`main.py:151-292`) *is* the pipeline: all 8 stages run inline, each output threaded directly into the next. No stage abstraction, no runner, no per-stage timing, no uniform error handling. The seams carry **three different idioms**: Pydantic models (Stages 1-4), bare **dataclasses** (`AssetPlan`/`LayoutPlan`/`ResolvedPackage`, defined in their stage modules, not `models.py`), and **raw dicts** (`components`, the hand-built `brand_axes` at `main.py:255-260`, `brand_tokens.model_dump()`). Stages that take "pages" each re-implement a `_unpack_page` dict-or-Pydantic normalizer (`plan_layout.py:108`, `generate_assets.py:528`) — duplicated defensive code that exists *because* the contract type isn't pinned. Notably the repo **already has the right-sized pattern**: `stages/onboard/pipeline.py` is a dedicated orchestrator with `_mark()` per-layer timing and one top-level fail-soft `try/except`. `/render` is the odd one out.

**Decision.** Adopt a **small hand-rolled `Stage` Protocol + runner (~60-100 LOC, stdlib)** — reject all third-party orchestration. Hamilton solves a *branching-DAG* problem this strict 8-node line doesn't have; Prefect/Dagster are *server platforms* for scheduling/multi-system fleets — massive overkill at checkbox volume (the InDesign-Server-class rejection). For contracts, use **explicit per-stage typed returns**: every seam becomes a Pydantic model *or* a documented dataclass — no bare dicts. Keep the dataclass-vs-Pydantic split intentional (Pydantic for anything serialized to the response/`resolved_package.json`; dataclasses fine for in-memory heavy objects like `LayoutPlan` that hold SVG/HTML strings and are deliberately not serialized). A single God "context" object is *not* worth it — the explicit signatures document each stage's true inputs. Wins worth taking: per-stage timing (reuse `_mark`), one error policy, and **contract tests at each seam** (the biggest win — lets the brand-agnostic guard + types be asserted per stage). Resumability/checkpointing = YAGNI (a render is seconds; re-run wholesale).

**Migration:** lock the current `resolved_package.json` with a characterization test → define `Stage`+`run_pipeline` in `stages/pipeline.py` → extract the route body into `run_render_pipeline()` (pure move) → tighten one seam at a time (typed `ComponentSet`; move `brand_axes` into a resolver; drop mid-pipeline `.model_dump()`), collapsing the `_unpack_page` duplication → add per-seam contract tests.
*Sources:* [Hamilton vs Dagster (micro- vs macro-orchestrator)](https://hamilton.dagworks.io/en/latest/code-comparisons/dagster/); [Airflow vs Prefect vs Dagster 2026](https://dev.to/datastackx/airflow-vs-prefect-vs-dagster-picking-the-right-orchestrator-in-2026-1ifb); [Pydantic v2 model-transformation guidance](https://docs.pydantic.dev/latest/concepts/experimental/); internal precedent `stages/onboard/pipeline.py`.

## Finding B — FastAPI structure, async model & job handling

**Current state.** `/onboard` (`main.py:85-142`) is the *good* pattern: returns **202** immediately, runs in `BackgroundTasks`, POSTs the result to a webhook with a manual retry loop + disk fallback. `/render` (`main.py:150-292`) is the opposite: **one long synchronous async request** that does image downloads + a Sonnet call + **fal generation** (180s/image, sequential) + assembly all in the request lifecycle — minutes of wall-clock, a timeout risk behind any proxy/n8n. The whole app is a single `main.py` — no `APIRouter`, no `Depends`, no `lifespan`. Every external call builds its **own** `httpx.AsyncClient` (no pooling) — **but every stage function already accepts `http_client=None` and self-constructs only when absent**, so a shared pooled client is pure wiring.

**Decision.** (1) **Add `lifespan` + one pooled `httpx.AsyncClient` + `Depends`-injected `Settings` now** — highest value / lowest risk, because the stage signatures are already shaped for it. (2) **Bring `/render` onto the 202 + background + webhook pattern**, but keep *cheap* Stage-1 validation synchronous (preserve immediate "reject loud"); background only the expensive Stages 5/8. (3) **Stay on `BackgroundTasks`** — matches FastAPI's own guidance for in-process tasks; reach for **arq** (asyncio + Redis, job ids/status, auto-requeue) only if durable retries / a status endpoint / concurrency force it; **Celery is out-of-scope overkill** at this volume. (4) Webhook-on-complete (n8n handles inbound webhooks natively) is the right delivery; a persisted job-status endpoint is YAGNI now.

**Migration:** lifespan + pooled client + Settings DI (no behavior change) → optional `APIRouter`/service split → async-ify `/render` (mirror `/onboard`, update `test_render_endpoint.py` to assert 202 + delivered payload, exactly as `test_onboard_endpoint.py` already does).
*Sources:* [FastAPI Background Tasks "Caveat"](https://fastapi.tiangolo.com/tutorial/background-tasks/); [BackgroundTasks vs arq+Redis (2026)](https://davidmuraya.com/blog/fastapi-background-tasks-arq-vs-built-in/); [Choosing a Python task queue](https://judoscale.com/blog/choose-python-task-queue); [Designing httpx clients in FastAPI — share one AsyncClient via lifespan](https://blog.greeden.me/en/2026/04/14/practical-introduction-to-designing-external-api-clients-in-fastapi-building-resilient-integrations-with-httpx-timeouts-retries-connection-pools-and-failure-isolation/); [Azure async request-reply pattern](https://learn.microsoft.com/en-us/azure/architecture/patterns/asynchronous-request-reply).

## Finding C — Resilience for external calls

**Current state (the inconsistency is real).** **fal generation** (`generate_assets.py:267-377`) uses the *synchronous* `fal.run/{model}` with **zero retry on the POST** and **no idempotency** — any re-run or wrapping retry **re-pays**; only the *download* of an already-generated image retries (correctly scoped). **Downloads** (`:174-215`) retry on `{429,5xx}` but with **linear `0.5*attempt` backoff, no jitter, and `Retry-After` ignored**. **All three OpenRouter calls** (prompt/vision/brief) are **single-attempt** and swallow failures to `{}`/`None` (intentional graceful degradation, but a single transient 429 needlessly loses the quality upgrade). **Webhook** (`main.py:116-142`) is a tight 3-attempt loop with **`except httpx.HTTPError: pass`** — silent, no backoff, no jitter. No caching/idempotency/budget logic exists anywhere; only `httpx` is installed.

**Decision.** Adopt **`stamina`** (opinionated tenacity wrapper — exp backoff + jitter by default, async-native) and one shared brand-agnostic policy module: max 3 attempts (max **2** for the costly fal POST), retry only `TransportError/TimeoutException` + `{429,500,502,503,504}`, **honor `Retry-After`**, explicit per-service `httpx.Timeout`s (keep current values). **fal idempotency (highest-value money saver):** content-addressed cache (`sha256(model+prompt+aspect+resolution+format)` → skip POST if cached) **+** the fal **queue `request_id`** to re-fetch results without re-paying. **Budget guard:** env `MAX_GENERATIONS_PER_REPORT` → degrade extras to `stub_not_generated` + warning. **Formalize graceful degradation** ("external call failed → stub + warning, never raise" — already true for LLMs; make it the documented contract and ensure *every* swallowed failure adds a warning string; the webhook currently doesn't). **Circuit breaking: do not add** — one sequential run, nothing to protect; the budget guard already bounds blast radius.

**Migration:** add `stamina` → route all call sites through the shared helper (tests inject `MockTransport`, and `stamina.set_active(False)` avoids wall-clock sleeps) → add the fal cache → add the budget guard (high default so fixtures never trip) → optionally switch fal to the queue last.
*Sources:* [stamina](https://stamina.hynek.me/); [tenacity](https://tenacity.readthedocs.io/); [fal queue API — request_id / auto-requeue](https://fal.ai/docs/model-apis/model-endpoints/queue); [fal reliability / 429 backoff](https://fal.ai/docs/documentation/model-apis/inference/reliability); [OpenRouter rate limits — honor Retry-After](https://openrouter.ai/docs/api/reference/limits); [httpx timeouts](https://www.python-httpx.org/advanced/timeouts/).

## Finding D — Config / secrets / observability / error-handling / testing

**Current state.** **Config:** 10 inline `os.getenv` in `main.py` only, with inline default model slugs; **no `BaseSettings`/`pydantic_settings`/`load_dotenv` anywhere** (verified) — `.env` loads *only* via `uvicorn --env-file`, so tests/scripts silently get defaults. **Observability: literally zero** — no `logging`/`print`/`structlog`/`otel` in app code; a `job_id` is minted for onboard but never threaded into the pipeline or emitted; `/render` has no correlation id. **Error handling:** Pydantic 422 + Stage-1 error envelope are good, but the long pipeline (`main.py:188-292`) has **no top-level try/except** (an uncaught fal/IO raise → bare 500, no log, no partial result), and there are two **truly silent** `pass` blocks (`main.py:132,139`). The dominant pattern elsewhere is sound (**fail-soft, record the reason in the returned payload, never raise**) — it just lands nowhere queryable. **Testing:** 221 unit tests, all external calls faked (`MockTransport`/`patch`/`monkeypatch`) = zero spend; `test_render_endpoint.py` already drives `/render` e2e (keys unset → stub path). But seam assertions are **piecemoeal field checks** — **no full golden-file snapshot, no JSON-Schema contract**, and the manifest is emitted as a raw dict (`PACKAGE_SCHEMA_VERSION="1.0"` exists but nothing validates against it).

**Decision.** (1) **Central `Settings(BaseSettings)`** in `config.py` (`SecretStr` keys, model slugs, timeouts, dirs; `env_file=".env"`), `@lru_cache` + `Depends`. (2) Keep the `.env`/`.env.example`/gitignore pattern (right-sized); inject via the platform var-store in prod (no code change). (3) **Structured logging** (stdlib + JSON formatter, or **structlog** for effortless `contextvars` job-id propagation across async stages) + a `job_id` on both routes; **replace the two silent `pass` blocks** and add a `logger.warning` at each structured-failure site **without changing the fail-soft return**. **OpenTelemetry: not now** (needs a collector to be useful) — clean 2-line upgrade path later. (4) **Error taxonomy** (`PreprocessorError` → `ExternalCallError`/`AssetGenerationError`/`PackageAssemblyError`) + `add_exception_handler` returning the *same* envelope the routes already use (so `/render` never bare-500s) — fail loud only at the route boundary; warn-never-block everywhere else (preserve advisory validators). (5) **Testing priority:** golden-file contract test on `resolved_package.json` → **promote the manifest to a Pydantic `ResolvedPackageManifest`** (validate-then-dump) → explicit e2e success-envelope test → Hypothesis property tests on the free-form per-page `data` → an error-path test asserting the new handler returns the envelope (not 500). All stay mocked.

**Flag (out of charter, surfaced honestly):** `.env` holds **live, un-rotated** OpenRouter + fal keys in plaintext (gitignored, not committed). *Prior decision on record: rotation deemed unnecessary.* Re-confirm; rotating costs nothing and `BaseSettings` makes the swap a config-only change.
*Sources:* [FastAPI Settings + lru_cache](https://fastapi.tiangolo.com/advanced/settings/); [Centralizing FastAPI config with pydantic-settings](https://davidmuraya.com/blog/centralizing-fastapi-configuration-with-pydantic-settings-and-env-files/); [Structured logging in FastAPI (2026)](https://oneuptime.com/blog/post/2026-02-02-fastapi-structured-logging/view); [structlog stdlib integration](https://www.structlog.org/en/stable/standard-library.html); [FastAPI handling errors](https://fastapi.tiangolo.com/tutorial/handling-errors/); [otel-instrumentation-fastapi](https://pypi.org/project/opentelemetry-instrumentation-fastapi/).

## Finding E — Modularity & Stage-6 deprecation

**Current state.** A flat `stages/` package + a `stages/onboard/` sub-package + a `models.py` hub (446). Most stage files are healthy (76-320 lines). Three exceed the ~500-line "consider splitting" line: `generate_components.py` (1,580), `generate_assets.py` (822), `validate_cover.py` (784).

**Stage-6 verdict: DEPRECATE (confirmed by consumer trace, not premature).** The chain is connected on the *write* side but **dead on the render side**: `main.py:236` → `plan_layout.py:185` → `assemble_package.py` writes `components/{slot}_component_{i}.svg` and indexes them in the manifest — but in the renderer, **only `patterns/_generic.py:135` reads `page["components"]`, and `_generic` is never dispatched for the ST types Stage 6 targets** (every dedicated pattern — `st_06/09/14/07a` — builds its visual from `page["data"]` via the renderer's own `_components` HTML builders). The committed apex package contains **exactly 1** Stage-6 SVG (slot 16, ST-06), and `st_06.py` ignores it. The prerequisite ("renderer must own charts first") is **already met today**. **Safe sequence:** keep the manifest `components` field (renderer reads it defensively) → neutralize the producer (`components = {}` in `main.py`) → observe a stable render → delete `generate_components.py` + `test_generate_components.py` + the two fixture imports → (later) strip the now-vestigial plumbing. Removes ~1,980 lines + the stale-Inter geometry liability.

**Other modularity (scale-honest).** **Split `generate_assets.py`** (its docstring names 4 jobs) into `stages/assets/` (`download.py`, `fal_client.py`, `prompts.py`, `inventory.py`) — the one split with clear payoff (it's exactly what the resilience work touches). **`validate_cover.py`** — optional light split of the H/S/B matrices; defensible to leave. **`models.py` (446) — leave as-is** (already sectioned; a single contract hub helps a small team; revisit past ~600-700). **`stages/`↔`stages/onboard/` boundary is correct** (onboard is a genuinely separate pipeline). No `clients/` package needed at this volume.
*Sources:* [Meta — automating dead-code cleanup](https://engineering.fb.com/2023/10/24/data-infrastructure/automating-dead-code-cleanup/); [Dead Code Removal at Meta (FSE 2023)](https://yia.nnis.gr/publications/fse2023.pdf); [Python module-split best practice (~500-line threshold)](https://www.tutorialspoint.com/article/how-many-python-classes-should-i-put-in-one-file).

## What this means for our build

- **The pre-processor is NOT vibe-coded where it counts** — the *logic* is typed, tested, and brand-agnostic. What's missing is the cross-cutting *infrastructure* layer (config, observability, resilience, explicit contracts) that turns a working prototype into a robust system. That's a well-bounded, additive body of work — not a rewrite.
- **Sequencing = the tiers above.** Tier 0 (config + pooled client + logging) is the cheap foundation everything else rides on, and the stage signatures are already shaped for it. Tier 1 protects real money (fal idempotency + budget) and the most important artifact (the `resolved_package.json` contract). Tier 2 is legibility/testability (pipeline runner + typed seams + async `/render`). Tier 3 deletes the Stage-6 liability.
- **Coupling to the renderer roadmap:** Stage-6 retirement is safe to do *now* (the renderer already owns visuals), but it's natural to land it alongside renderer **Plan B** so the "renderer builds all charts from data" story is proven end-to-end in one pass.
- **Methodology unchanged:** each tier becomes a spec → plan → subagent-driven TDD build, every step output-preserving and verified against the 221-test net (the pre-processor analog of the renderer's visual-regression gate is the new golden-file/contract test on `resolved_package.json`).
- **Recommended next step:** user picks the tier(s) to greenlight → write a **pre-processor architecture-migration spec** (mirroring the renderer's), then plan + build tier-by-tier. Nothing here changes behavior; it makes the working behavior robust, observable, and cheap to extend.
